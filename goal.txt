持续将固定版本的 `/root/app/esper` Esper 9.0.0 完整移植到当前
`bigsoc-esper` 仓库。Java Esper 是可观测行为 oracle；Go 公共规则 API
必须是符合 Go style 的类型安全链式 API，体验参考 Flink，不以 EPL 文本
作为主要入口，也不机械复制 Java 类结构。

本项目使用 Oh My Pi（OMP）长期执行。项目约束由 `.omp/AGENTS.md` 和
`.omp/RULES.md` 自动加载；具体流程使用：

- `docs/esper-go-port-roadmap.md`：当前优先级和 remaining；
- `testdata/compat/capability-manifest.json`：进度和验证状态的机器事实；
- `docs/esper-go-port-runbook.md`：工作单元、门禁、提交和恢复；
- `docs/esper-go-port-quality-strategy.md`：差分、合成数据和最终验收；
- `docs/esper-go-port-omp-workflows.md`：OMP 并行拓扑和 task 模板。

持续以一个可闭环工作单元为粒度推进：选择同一 capability 子域内 1 至
5 个紧密相关 Java executions，确认 Java source/runtime IDs 和可观测
契约，用确定性合成 scenario 生成固定 Java trace，实现等价 Go 链式
API，自动比较规范化 Java/Go trace，补齐边界、状态序列和必要 mutation，
再更新 manifest、evidence、roadmap/CHANGELOG 等受影响事实。

优先用 OMP `task` 批量并行只读调查；共享 `internal/esper` 语义一次只能
有一个实现写入者。只有依赖契约已冻结且语义/文件真正独立的组件才使用
`isolated: true` 并行实现。子 agent 不运行 formatter、lint 或测试，不
commit/push；主 agent 集成后统一运行定向验证、差分和完整本地门禁，
再调用 `parity-reviewer` 独立审查。具体任务必须使用
`# Target / # Change / # Acceptance` 契约和 strict 结构化回传。

以“已验证工作单元吞吐量”而不是单个 agent 利用率优化调度，并维持最多
一个未来工作单元的只读预取队列。工作单元 N 完成集成和定向验证后，必须
用同一个 `task` batch 同时启动：N 的 `parity-reviewer`、N+1 的 Java
契约调查、N+1 的 Go 实现面调查。review 期间主 agent 继续完成 N+1 的
只读契约整理；只要仍有安全的只读工作，就不得立即进入 `hub wait`。
若只能启动 singleton task，必须先说明不存在可安全并行的 sibling task。

契约冻结后，允许一个 shared-core writer 与一个 `parity-asset-worker`
并行，前提是文件所有权完全不重叠：前者独占共享 runtime/API 语义，后者
只写明确分配的 Java oracle、scenario 输入或独立 Go parity test。trace、
evidence、manifest、roadmap 和 CHANGELOG 仍由主 agent 在集成验证后统一
生成或更新。N 审查期间不得开始 N+1 的写入，避免污染 reviewer 的 diff。
同一 work unit 的修复结果回传给原 worker/reviewer 复核，不为同一范围重复
启动失去上下文的新 agent。共享同一 runtime surface、oracle harness 和
验证命令的紧密 executions 应在风险允许时合并，摊薄 review 和门禁成本；
不得为了制造更多 work unit 而把一个自然闭环拆成多个微小提交。

任何已有门禁失败时停止新增功能，先恢复绿色基线。不得通过 Skip、删除
测试、放宽断言、修改 oracle 迎合 Go、伪造 evidence 或滥用
`intentionally-different` 绕过失败。`implemented` 不等于 parity；只有
具备可重放 scenario、两端 trace、零差异 evidence 和 runtime IDs 才能
登记 `differential-verified`。

项目暂不建设 GitLab CI，也不保护 `master`。每个工作单元经主 agent
完整验证后，创建一个语义完整、可回退的提交并直接推送 `master`；禁止
提交或推送已知失败状态，禁止覆盖用户无关修改。

可以按需安装工具、使用固定版本的第三方 Go 库或启动 Docker。持续执行，
直到 `docs/esper-go-port-quality-strategy.md` 的最终验收条件全部满足；在此
之前不得宣称完整 Esper 对等、完全兼容或可直接替换 Java。
