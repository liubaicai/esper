# Esper Go

Esper 9.0.0 的 Go 移植正在按 [实施规划](docs/esper-go-port-implementation-plan.md) 进行。规则使用可分析的 Go 链式 Builder 构造，核心路径不接受 EPL 字符串。

本轮结果集切片补充了索引化 `First`/`Last`/`Nth`、`WindowEvents`/`EventValue`、`MinByEver`/`MaxByEver`、带过滤器的有状态 `Leaving`、常量/过滤速率与 `RateByTimestamp`/数量速率、多条件 `SortedEvents`、外层分组可嵌套的 `LocalGroupBy`、`SortedAccessBy` 导航访问、无参数 `Method`/属性链、命名及环境注册式 `PluginAggregate`、按组隔离的 `AggregatePluginFactory`（含 `Enter`/`Leave`/`Value`/`Clear`）、context-partitioned rollup/FAF 聚合、确定性 `CountMinSketchAdd`、`TableSink` 聚合落表、链式 `AggregateStream.IntoTable` 原子快照同步、live table snapshot join，以及聚合投影别名 `ResultField` 的 order-by/having 语义；对应 Java 来源和 runtime ID 已登记在 `compat/capability-manifest.json`。这些能力仍是 mapped/partial 切片，不能解读为 Esper 聚合全量对等。

EsperIO 已开始落地 Go 垂直切片：`connectors/csv` 提供 CSV/File source、unformatted line source、CSV sink、Java 风格标题行/类型转换、loop/reset、固定速率/时间戳回放、Esper Event/Row bridge；`connectors/db` 提供 database/sql DML/Upsert sink、绑定、重试、prepared statement 生命周期和 MySQL round-trip；`connectors/http` 提供 HTTP client/server source/sink、query/property URI 模板、JSON body、响应上限、重试、暂停/重启和 Engine bridge；`connectors/socket` 提供 TCP source、OBJECT/CSV/PROPERTY_ORDERED_CSV/JSON、Java escape、多连接、暂停/重启、typed Engine bridge 和可注册 object decoder；`connectors/kafka` 提供 kafka-go Reader/Writer、JSON processor、commit/retry/timestamp、key/header/有序 JSON 输出和 Engine bridge；`connectors/amqp` 提供 RabbitMQ Consumer/Publisher、queue/exchange/binding、prefetch、JSON/GOB codec、auto/manual ack、reject/requeue、retry 和 Engine bridge；`connectors/jms` 提供 provider-neutral Spring JMS bridge contract、Map/Text/Object/Bytes codec、Java event-type property、ack-after-process 和 channel transport；七者都使用统一 `OPENED/STARTED/PAUSED/DESTROYED` 生命周期。Java `esperio-csv` Maven 模块 80/80 通过，`esperio-db` 的 2/4 环境结果、`esperio-http` 的 3/4 结果、`esperio-socket` 的 7/7 结果，以及固定 Kafka 3.8.1 KRaft 环境下 `esperio-kafka` 的 6/6 结果已登记到 capability manifest；Spring JMS 4 个测试中 1/4 通过且环境差异已记录，Go Kafka/RabbitMQ/JMS bridge 也通过。Kafka 高级 group/rebalance/plugin、AMQP Java serialization/高级重连、JVM JMS provider/session/transaction/Spring XML 和完整 Dataflow connector 集成仍在计划中。

运行测试：

```text

```

```powershell
$env:ESPER_MYSQL_DSN='root:password@tcp(127.0.0.1:3306)/test?parseTime=true&charset=utf8mb4'
go test -run '^TestSQL(Sink|HistoricalProvider)MySQLDocker$' -count=1
```

本轮新增基础五字段及可选秒/毫秒 `CronSchedule`/`OutputAt` 与 Pattern `TimerCron`：支持 `CronEvery`、`CronRange`、`CronWildcard`、变量/参数字段、虚拟时钟下一次触发和日月/周 OR 语义；不等于 Esper 全部 cron 能力。

本轮继续补充 JSON provided-underlying 的 Go-native 泛型结构体适配：支持嵌套 slice/struct、JSON tag、UUID、`DateOnly`、`time.Time` 和 `big.Rat`，并通过 `Engine.SendJSON`/`RenderJSON` 验证解析、发送和渲染边界；同时覆盖 schema invalid、constructor-style primitive default、null projection route 和 pattern typed-array。JVM 专属的 public-class/default-constructor/non-static-inner-class 诊断记录为 Go 零值结构体模型的 API 差异。

本轮继续补齐 JSON VM-class/laxness 对照：新增 Go-native `URL`/`URI`，覆盖 UUID、时间、URL、URI 的 scalar/一维数组/二维数组/collection、null、shape mismatch 和渲染；覆盖 byte/short/int/long/float/double/BigInteger/BigDecimal 对应 Go 类型的字符串宽松转换及非法值诊断，并验证 malformed/trailing JSON 与 static/dynamic undeclared-field policy。typed 特殊标量的非法输入现在返回错误，不再静默变成 Null；随后又补齐 core dynamic JSON 的 string/number/bool/null/object/array、混合/嵌套数组和 `42.0`/指数数字词法 round-trip。Java class/list adapter 的其它约定、递归 schema/metadata、完整 nested/dynamic arbitrary-precision 格式和共享 parse-write trace 仍未完成。

本轮继续对照 `EventJsonTypingClassParseWrite`：`NewJSONSchemaFor[T]`/`ParseJSON`/`RenderJSON` 现在覆盖 class simple、递归 nested class、对象的一维/二维数组与 collection、基础类型/Character/rune/BigInteger/BigDecimal 列表、枚举样字符串列表，以及 UUID/LocalDate/LocalDateTime/OffsetDateTime/ZonedDateTime/URL/URI 的 scalar/数组/collection。新增用例固定 missing、null、empty、partial、schema 字段顺序、Character 字符串形态和 typed number lexeme；这组 JSON 对照不需要 MySQL Docker。

本轮继续补齐 `EventJsonTypingCoreParse/CoreWrite`：`json_core_parity_test.go` 直接覆盖基本 scalar、Character 多字符取首 code point、wrapper/primitive 一维与二维数组、enum、`big.Int`/`big.Rat`、`Object`/`Object[]`/`Map` 容器，以及嵌套 BigDecimal 对象和数组的解析/渲染矩阵；`RenderJSON` 对 Character 恢复单字符 JSON string。Core JSON 定向测试通过，Java `TestSuiteEventJson` 13/13 仍通过；递归 schema/metadata、完整 dynamic strict-lax、所有 nested/dynamic arbitrary-precision 格式规则和共享 Java/Go trace 仍保持 partial。本轮不需要 MySQL Docker。

本轮再次复核 JSON 遗漏入口：新增 `Engine.JSONSender`/`JSONEventSender` 的解析、发送和路由链、同名异构 schema 的 identity 防串型、`Schema.Getter` 的 schema-bound mapped getter、特殊字段名与 JSON/Map nested-schema 校验，以及显式泛型 `NewJSONFieldAdapter`/`NewNamedJSONFieldAdapter`/`WithJSONFieldAdapter` 的 string↔typed 双向转换、null 保留、类型/输入错误诊断和 Plan identity；同时覆盖 DocSamples 的 Book/Cake nested、dynamic empty、application class 和显式 Environment catalog boundary。sender dispatch 保留 JSON 原始字面量，Java `EventSenderJson`/`EventPropertyGetter`/annotation class-loader/module visibility 则以 Go 显式对象、函数注册和 catalog 隔离替代；完整 fragment/metadata 与 Java module/path 语义仍未完成。本轮不需要 MySQL Docker。

本轮继续补齐 typed JSON 的嵌套 fragment 元数据：struct-valued scalar/indexed 字段会自动生成稳定的 `NestedSchema`，递归指针复用有限 schema 图；新增 `NestedSchemaNames`/`FragmentSchema`、深层 schema-bound getter、`Event.GetFragment`/`GetFragments` 和 null-versus-empty nested-array 渲染对照，显式 `WithNestedPropertySchema` 仍优先。新增 `WithNestedPropertySchemaFrom`，可从显式 `Environment` catalog 解析独立注册的命名 JSON/Map fragment，并覆盖 Java `Friend[]`/`User[]` create-schema 形态、缺失/跨环境诊断和 JSON→Map fragment。该切片对照 Java `EventJsonTypingNestedRecursive`、`EventJsonTypingClassWArrayAndColl` 和 `EventJsonProvidedClass*WithCreateSchema` 入口，但完整 catalog 生命周期、全表示 fragment metadata、模块可见性和共享 parse-write trace 仍保持未完成。
