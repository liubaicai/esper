# Esper Go

Esper 9.0.0 的 Go 移植正在按 [实施规划](docs/esper-go-port-implementation-plan.md) 进行。规则使用可分析的 Go 链式 Builder 构造，核心路径不接受 EPL 字符串。

本轮结果集切片补充了索引化 `First`/`Last`/`Nth`、`WindowEvents`/`EventValue`、`MinByEver`/`MaxByEver`、带过滤器的有状态 `Leaving`、常量/过滤速率与 `RateByTimestamp`/数量速率、多条件 `SortedEvents`、外层分组可嵌套的 `LocalGroupBy`、`SortedAccessBy` 导航访问、无参数 `Method`/属性链、命名及环境注册式 `PluginAggregate`、按组隔离的 `AggregatePluginFactory`（含 `Enter`/`Leave`/`Value`/`Clear`）、context-partitioned rollup/FAF 聚合、确定性 `CountMinSketchAdd`、`TableSink` 聚合落表、链式 `AggregateStream.IntoTable` 原子快照同步、live table snapshot join，以及聚合投影别名 `ResultField` 的 order-by/having 语义；对应 Java 来源和 runtime ID 已登记在 `compat/capability-manifest.json`。这些能力仍是 mapped/partial 切片，不能解读为 Esper 聚合全量对等。

EsperIO 已开始落地 Go 垂直切片：`connectors/csv` 提供 CSV/File source、unformatted line source、CSV sink、Java 风格标题行/类型转换、loop/reset、固定速率/时间戳回放、Esper Event/Row bridge；`connectors/db` 提供 database/sql DML/Upsert sink、绑定、重试、prepared statement 生命周期和 MySQL round-trip；`connectors/http` 提供 HTTP client/server source/sink、query/property URI 模板、JSON body、响应上限、重试、暂停/重启和 Engine bridge；`connectors/socket` 提供 TCP source、OBJECT/CSV/PROPERTY_ORDERED_CSV/JSON、Java escape、多连接、暂停/重启、typed Engine bridge 和可注册 object decoder；`connectors/kafka` 提供 kafka-go Reader/Writer、JSON processor、commit/retry/timestamp、key/header/有序 JSON 输出和 Engine bridge；`connectors/amqp` 提供 RabbitMQ Consumer/Publisher、queue/exchange/binding、prefetch、JSON/GOB codec、auto/manual ack、reject/requeue、retry 和 Engine bridge；`connectors/jms` 提供 provider-neutral Spring JMS bridge contract、Map/Text/Object/Bytes codec、Java event-type property、ack-after-process 和 channel transport；七者都使用统一 `OPENED/STARTED/PAUSED/DESTROYED` 生命周期。Java `esperio-csv` Maven 模块 80/80 通过，`esperio-db` 的 2/4 环境结果、`esperio-http` 的 3/4 结果、`esperio-socket` 的 7/7 结果，以及固定 Kafka 3.8.1 KRaft 环境下 `esperio-kafka` 的 6/6 结果已登记到 capability manifest；Spring JMS 4 个测试中 1/4 通过且环境差异已记录，Go Kafka/RabbitMQ/JMS bridge 也通过。Kafka 高级 group/rebalance/plugin、AMQP Java serialization/高级重连、JVM JMS provider/session/transaction/Spring XML 和完整 Dataflow connector 集成仍在计划中。

运行测试：

```text
go test ./...
go test -race ./...
```

启用本地 MySQL Docker 集成测试（可选）：

```powershell
$env:ESPER_MYSQL_DSN='root:password@tcp(127.0.0.1:3306)/test?parseTime=true&charset=utf8mb4'
go test -run '^TestSQL(Sink|HistoricalProvider)MySQLDocker$' -count=1
```

本轮新增基础五字段及可选秒/毫秒 `CronSchedule`/`OutputAt` 与 Pattern `TimerCron`：支持 `CronEvery`、`CronRange`、`CronWildcard`、变量/参数字段、虚拟时钟下一次触发和日月/周 OR 语义；不等于 Esper 全部 cron 能力。

示例位于 `examples/stage1`。当前仍是增量移植，不能宣称完整 Esper 对等：枚举/集合方法的完整 Java 类型与无效规则校验、BigDecimal/任意集合类型、复杂嵌套/子查询/访问聚合组合（当前仅有 Named Window/Table 基础子查询）、ROLLUP/CUBE/GROUPING SETS 的组合 grouping specification/Join/Context/FAF/output 全矩阵，Variant 的完整 insert-into/derived stream/wrapper 转换矩阵、late schema、supertype/identity 和完整 ANY 动态属性矩阵，Join/Aggregate/Pattern/Named Window 路由的完整混合 new/old 顺序、事件表示/转换和可配置循环策略，完整多流/子查询 Join，历史 SQL 的方言占位符、metadata-origin/类型映射、连接池/事务/连接生命周期、DML/Upsert、方法流和多源 FAF/Context 约束，完整聚合和输出策略（filtered/math-context/访问聚合、cron 微秒精度、特殊日历运算符、完整 when/then 上下文与更多计数函数、完整 snapshot-after/grouped delivery 等；日历 after 目前只覆盖非负 years/months/days 的固定周期）、Pattern guard/observer timer-schedule/consumption 及 Match Recognize 的复杂 NFA/prev/interval/after/聚合/窗口删除语义、Context selector/嵌套/全生命周期、Dataflow 类型化多端口/信号/背压、完整事件格式与 Serde、EsperIO 其余传输连接器及完整 Dataflow/trace parity、Java/Go 全量行为差分和源测试映射仍按规划继续实现。Java 运行态 execution 清单已生成在 `compat/java-execution-inventory.jsonl`，但它不等于 Go 已通过对照。

Java 基线的静态回归候选清单在 `compat/static-manifest.json`，运行态 execution 清单在 `compat/java-execution-inventory.jsonl`，非 Regression 的源资产盘点在 `compat/source-test-manifest.json`，首批 capability/case 映射在 `compat/capability-manifest.json`；这些清单都不是全量 Go 映射完成或 Java/Go 行为差分通过的证明。
